## 2) إزالة الملفات الشخصية من تاريخ Git (F-13)

- **الجرد**: 18 ملفاً تحت `upload/` (~6.7 MB) بينها صور شخصية (`portrait-src.jpg`،
  `profile-edited.png`، `Dofoto_٢٠٢٦٠٦٢٢_…`)، لقطات شاشة، و`note_1030_111000248.pdf` —
  موجودة في تاريخ `main` وفروع الميزات الثلاثة.
- **الخطوات**:
  1. نسخة احتياطية **قبل** إعادة الكتابة: `cto-drs-pre-rewrite.bundle` (كل الفروع والتاغات).
  2. حذف الملفات من الشجرة الحالية + قاعدة `.gitignore` جديدة `upload/` (F-13).
  3. `git filter-repo --invert-paths --path upload` على مستودع مستنسخ نظيف — إعادة كتابة
     كل الفروع، بلا أي commit يحمل المجلد بعد ذلك.
  4. دفع قسري لكل الفروع، ثم bundle **بعد** الكتابة أصغر حجماً (معيار القبول).
- **النتيجة الفعلية**:
  - إعادة كتابة **90 التزاماً**؛ `main` من `5a38c05` إلى `6c25b5e`، و`feat/supabase-auth`
    من `9dd3e57` إلى `572295b`، و`published-site` من `f2c0823` إلى `f67d1c0`
    **بشجرة مطابقة بيتياً** (محتوى الموقع المنشور لم يتغير حرفاً واحداً)، بينما
    `gh-pages` تاريخ مستقل لم يمسّه التطهير (`6b311fd` بلا تغيير).
  - حجم الحزمة: **34.10 → 28.25 MiB** (انخفاض ~17%).
  - التحقق النهائي: `git log --all --name-only` على كل فرع بعد الكتابة → **صفر** مسارات
    `upload/`، ونسخة استنساخ نظيفة جديدة لا تحوي أي ملف شخصي.
- **ملاحظة شفافة حول بقايا GitHub الداخلية**: مراجع الـ PR المدموجة (`refs/pull/1/head`
  و`refs/pull/2/head`) وسجلات خوادم GitHub تحفظ نسخاً من الالتزامات قبل الكتابة، ولا
  يمكن تعديلها عبر الـ API — الاستنساخ العادي (`git clone`) لا يجلب هذه المراجع
  إطلاقاً، فلا تظهر الملفات في أي نسخة عمل عادية. إن لزم الإزاحة الكلية على مستوى
  المنصة لاحقاً فالطريق الموثق طلب إلى GitHub Support لحذف المراجع الداخلية والكائنات
  غير القابلة للوصول (Unreachable objects). حُذف أيضاً فرع `chore/p2-card` المدموج
  حتى لا يبقى مرجعاً حياً على الالتزامات القديمة.
- **معيار القبول (F-13)**: لا صور شخصية أو PDF في أي commit تاريخي — تحقق ✅، وحزمة
  الـ bundle أصغر حجماً — تحقق ✅.

## 3) تفعيل reactStrictMode (F-14)

- `next.config.ts`: `reactStrictMode: true` — الوضع الصارم مفعّل في التطوير ويكشف
  الأعراض الجانبية والاستدعاءات المزدوجة مبكراً؛ لا تأثير في الإنتاج.
- **معيار القبول (F-14)**: تشغيل dev نظيف — التحقق العملي: خادم التطوير جاهز بلا أي
  تحذير React أو خطأ (`dev.log` فارغ من التحذيرات)، وعند جلب الصفحة الرئيسية
  استجابة 200 بحجم ~279KB. أساس ذلك أن إصلاحات React Compiler في بطاقة P1 أعادت
  هيكلة كل أنماط `setState` داخل الـ effects التي كانت ستصدر تحذيرات صارمة.
